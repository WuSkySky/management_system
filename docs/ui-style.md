# 前端风格记录

状态：**用户已确认**（2026-09-28）。适用于之后的生产管理系统界面设计，手机和电脑都需要良好使用。

## 已确认的方向

1. 整体要超级简洁，以信息清晰、易读和操作直接为目标。
2. 使用干净的背景、克制的颜色，以及字号、字重、留白和对齐建立层级。避免大量浅色色块或卡片堆叠。
3. 少用分割线。优先用间距和对齐区分区域；只在确实有助于识别边界或当前选择时使用线条。用户已看过并认可减少分割线后的 Demo。
4. 页面文字标注保持简短。含义从位置或通用图形可以明确理解时，不重复添加提示；可能产生误操作的动作、关键状态和无法仅靠图形理解的内容仍要清楚标明。
5. 状态颜色只作辅助。进度、受阻、完成等信息必须能从文字或数值辨识，不能只靠颜色判断。
6. 同一套视觉语言适配桌面和手机；具体导航形式和信息排布按实际使用场景设计。

## 可参考的 Demo

- [reference/style-demo/src/style.css](../reference/style-demo/src/style.css)：白底、深色文字、克制的绿色强调色、少量异常提示色、较少分割线，以及通过留白组织信息的方式。
- [reference/style-demo/src/main.js](../reference/style-demo/src/main.js)：简短标签、状态与进度的展示方式，以及桌面和手机视图切换的示意。
- 运行方式：进入 `reference/style-demo/`，执行 `npm install` 和 `npm run dev`。

Demo 中的**颜色、字号、留白和具体间距都只是参考**，不是硬性约束或固定设计令牌。后续可以根据页面内容、信息密度、设备尺寸和可读性调整这些参数；不必照搬 Demo。实现新页面时，以真实业务需求和易用性为准，整体保持简洁、克制的方向即可。

## 明确不是需求定稿的部分

Demo 只是一个展示风格的虚构“生产概览”页。它的页面排版、栏目数量、侧边栏和底部导航、字段、指标、进度算法、异常文案、品牌名“序线”、示例订单和数据，都**不应被视为最终产品需求**。后续页面结构、内容、路由、权限和交互流程，必须根据用户之后提供的业务需求确定。
