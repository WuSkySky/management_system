# 生产管理系统

内部使用的机器零件管理系统。每台机器有预计完成日期和零件列表；零件通过采购或生产线路取得，负责人按步骤推进状态。项目目前在本地开发，尚未部署到 Cloudflare。

后续迭代先读本 README，再按需查看 [业务规则](docs/business.md)、[角色权限](docs/roles.md)和[界面风格](docs/ui-style.md)。`reference/style-demo/` 是独立的视觉参考，不是产品页面或业务需求。

## 已实现的页面

| 路径 | 页面 | 主要功能 |
| --- | --- | --- |
| `/login` | 登录 | 内部帐号登录，无注册和找回密码流程 |
| `/machines` | 机器 | 查看预计完成日期；管理员创建、编辑和删除机器；点击机器进入其零件页 |
| `/parts` | 零件 | 选择机器、查看零件及状态；管理员增删改零件，负责人推进自己负责的零件 |
| `/part-templates` | 零件模板 | 仅管理员可见；维护创建新机器时自动加入的零件 |
| `/admin` | 人员 | 仅管理员可见；创建、编辑和删除人员帐号 |

根路径进入机器页。所有页面的列表首次取数时显示“加载中…”，成功且没有数据时才显示空状态。零件页会在当前浏览器标签页记住上次选中的机器；从机器页点击进入时，以链接中的机器为准。

## 核心业务规则

- 机器名称全局唯一，填写预计完成日期；可以没有零件。距完成日期少于 15 天时，机器行显示剩余天数，逾期后显示逾期天数。
- 同一台机器内零件名称不可重复。每个零件选择一条采购或生产线路，并指定一位相应角色的负责人。
- 零件模板有名称、线路和负责人，模板名称全局唯一。创建机器时复制**当时**的全部模板并设置各线路初始状态；以后修改或删除模板，不会改动已有机器。
- 采购状态：未采购 → 已采购未付款 → 已付款未入库 → 已入库。按钮依次为“采购完成”“付款完成”“确认入库”。
- 生产状态：缺少原材料 → 生产中 → 已入库。按钮依次为“原料齐全开始生产”“生产结束入库”。状态只能逐步前进，已入库后没有推进按钮。
- 管理员可推进任意零件；采购、生产人员只能推进自己负责的零件。管理员修改零件线路时，状态重置到新线路的第一步。
- 删除机器需要二次确认，并同时删除其零件；删除单个零件直接执行。
- 人员姓名可重复，帐号名全局唯一且创建后不可修改。管理员可编辑姓名、密码和角色。有人负责机器零件或零件模板时不能删除，也不能改成与负责线路不符的角色；没有负责内容时，二次确认后可删除。

## 技术与代码位置

前端使用 Vue 3、Vue Router 和 Vite；后端使用 Hono 运行在 Cloudflare Worker；数据存储使用 D1。前后端通过同域 `/api/*` 通信，权限和状态推进规则由后端再次校验。

| 路径 | 用途 |
| --- | --- |
| `src/views/` | 五个页面的界面与交互 |
| `src/App.vue`、`src/router.ts` | 导航、路由和管理员页面守卫 |
| `src/business.ts`、`src/auth.ts` | 前端 API、业务类型、登录状态 |
| `src/style.css` | 全站样式及表格布局 |
| `server/index.ts` | API、会话、权限与业务校验 |
| `migrations/` | D1 表结构和初始管理员帐号 |
| `wrangler.jsonc` | Worker 与 D1 配置；当前数据库 ID 是本地占位值 |

主要 API：`/api/auth/*`、`/api/admin/users`、`/api/admin/users/:id`、`/api/admin/users/:id/assignments`、`/api/staff`、`/api/machines`、`/api/machines/:id`、`/api/machines/:id/parts`、`/api/parts/:id`、`/api/parts/:id/advance`、`/api/part-templates` 和 `/api/part-templates/:id`。修改前端交互时，请同时检查对应后端校验。

迁移按编号顺序执行：`0001` 建立登录相关表，`0002` 改为当前的明文密码字段并创建初始管理员，`0003` 建立三种角色，`0004` 增加机器与零件，`0005` 增加零件模板。`0002_plaintext_passwords.sql` 不会自动转换在该迁移之前已存在的旧哈希密码；升级旧环境时需单独处理那些帐号。

## 本地开发

需要 Node.js。首次启动或拉取新迁移后，在项目根目录执行：

```bash
npm install
npm run types
npm run db:migrate:local
npm run dev
```

## 帐号与权限现状

角色为 `admin`、`procurement`、`production`。所有登录人员都能查看机器与零件；只有管理员可以维护机器、零件模板和人员。管理员页面能查看帐号的明文密码，密码也按当前原型约定以明文保存在 D1 中。固定初始管理员凭据写在迁移文件里；能读取源码或数据库的人可以看到它。上线前应重新评估这套密码方案。

会话在服务端保存 7 天，浏览器使用 HttpOnly、SameSite=Lax Cookie，HTTPS 时启用 Secure；退出后会话失效。登录失败次数有限制，API 响应禁止缓存。

## 部署

项目尚未部署，部署由项目使用者执行。本地 D1 中的帐号和数据不会自动进入远程数据库。

1. 使用 Wrangler 登录 Cloudflare，创建名为 `management-system` 的 D1 数据库。
2. 将 `wrangler.jsonc` 中的占位 `database_id` 替换为真实数据库 ID。
3. 执行 `npm run types`、`npm run db:migrate:remote` 和 `npm run deploy`。
4. 部署后检查登录、角色权限、创建机器时复制零件模板以及状态推进。

远程迁移会创建固定初始管理员；部署前应确认该凭据和明文密码方案符合实际使用环境。
